Quick start

  1. Buy a game and copy your license key.
    In the dashboard, open the Store and buy a game. A secret license key (mgk_…) is shown once. Keep it on your server only.
  2. Add one endpoint to your backend.
    It calls POST {{HOST}}/api/v1/sessions with your key and returns the playUrl to your front-end (see Server API).
  3. Show the game.
    Open that playUrl in an iframe (website) or WebView (Flutter, Android, iOS, React Native). Players choose a username and play.
Want to try it before writing code? Open My games → your game → Customize. The preview on the right is the real game.

How it works

  • License key (mgk_…): the secret that proves the game is yours. One key per purchased game. Never put it in website JavaScript or inside a mobile app, because anyone can read those.
  • Session link (playUrl): a temporary link created by your server with the key. It expires after 15 minutes, so it is safe to hand to a browser or app.
  • Player: whoever plays. They pick a unique username the first time (or you pass their name from your own login so they skip that screen). Balances and history are saved on our server per username.
  • Customization: images, colors, currency name, prizes, bet sizes… all set in the dashboard. Every session automatically loads your settings, so the same game bought three times can look three different ways.

Server API: create a play session

POST {{HOST}}/api/v1/sessions

HeaderValue
AuthorizationBearer YOUR_LICENSE_KEY
Content-Typeapplication/json
Body fieldRequiredDescription
usernameno3-20 characters (letters, numbers, _ . -). If you send it, the player skips the username screen and is treated as that user. Use this when your app already knows the user.

Response 200:

{
  "playUrl": "{{HOST}}/g/lucky-spin/?session=eyJ0...",
  "sessionToken": "eyJ0...",
  "expiresIn": 900,
  "game": "lucky-spin"
}
StatusMeaning
401Missing or wrong license key (for example a key that was rotated)
403License is not active
400Invalid username
429Too many requests. Slow down and cache nothing longer than 15 minutes.

Example server code

Create a new session each time a player opens the game. Do not reuse or cache playUrl for more than a few minutes.

Website

Include the SDK and mount the game. /game-session is the endpoint you created above.

<div id="game" style="width:100%;max-width:480px;height:720px"></div>
<script src="{{HOST}}/sdk/minigames.js"></script>
<script>
  const game = MiniGames.mount('#game', {
    sessionEndpoint: '/game-session',          // your server endpoint (POST, returns { playUrl })
    onEvent: (e) => console.log(e.type, e.data) // ready | login | round | error
  });
  // game.reload()  creates a fresh session and reloads
  // game.destroy() removes the game
</script>

Prefer a plain iframe? Use the playUrl directly:

<iframe src="PLAY_URL_FROM_YOUR_SERVER" width="480" height="720" style="border:0" allow="autoplay; fullscreen"></iframe>

The games are designed for portrait screens (like a phone) and also work in any box on desktop: they scale to fit the height and fill the rest with your theme background.

React / Vue / Angular

Use the same two lines inside a component's mount hook, or render an <iframe> whose src is the playUrl you fetched from your backend.

Flutter, Android, iOS, React Native

Load the playUrl in a WebView. In Flutter:

# pubspec.yaml
dependencies:
  webview_flutter: ^4.9.0
  http: ^1.2.0

// game_screen.dart
import 'dart:convert';
import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;
import 'package:webview_flutter/webview_flutter.dart';

class GameScreen extends StatefulWidget { const GameScreen({super.key}); @override State<GameScreen> createState() => _GameScreenState(); }

class _GameScreenState extends State<GameScreen> {
  WebViewController? controller;

  @override
  void initState() { super.initState(); _open(); }

  Future<void> _open() async {
    // Ask YOUR backend (it holds the secret key). Never call the session API from the app itself.
    final res = await http.post(Uri.parse('https://your-backend.com/game-session'));
    final playUrl = jsonDecode(res.body)['playUrl'] as String;
    final c = WebViewController()
      ..setJavaScriptMode(JavaScriptMode.unrestricted)
      ..addJavaScriptChannel('MiniGames', onMessageReceived: (m) {
        final e = jsonDecode(m.message);        // { source, type, data }
        debugPrint('game event: ${e['type']} ${e['data']}');
      })
      ..loadRequest(Uri.parse(playUrl));
    setState(() => controller = c);
  }

  @override
  Widget build(BuildContext context) => Scaffold(
    body: SafeArea(child: controller == null ? const Center(child: CircularProgressIndicator()) : WebViewWidget(controller: controller!)),
  );
}

The game posts its events to a JavaScript channel named MiniGames if one exists (Flutter addJavaScriptChannel) and also to window.parent.postMessage (websites). React Native WebView's onMessage receives them too.

Android needs <uses-permission android:name="android.permission.INTERNET"/>. iOS needs no extra setup for https links.

Events from the game

Every event is { source: "minigames", type, data }.

typedataWhen
login{ username, balance }The player is signed in
ready{ game }The game is on screen
round{ game, bet, win, balance, … }A round finished. Lucky Spin adds multiplier, label; Lucky 77 adds lines, jackpot; Ludo adds placement.
error{ message }Web SDK only: your session endpoint failed

Events are for your UI (analytics, rewards in your own system, and so on). The authoritative record of every round is on our server and visible in your dashboard.

Customizing a game

Open My games → your game → Customize. Changes apply to new sessions immediately.

GameYou can change
Lucky SpinTitle, logo, background, colors, currency name, starting balance, bet sizes, up to 12 wheel segments (label, multiplier, odds weight, color, icon)
Lucky 77Title, logo, background, colors, currency name, starting balance, bet sizes, 3-8 reel symbols (label, payout multiplier, odds weight, color, image)
Ludo RoyaleTitle, logo, background, colors, the four player colors, currency name, starting balance, entry fee, 1st/2nd place payouts, bot difficulty

Uploads: PNG, JPG, WebP or GIF up to 2 MB. Transparent PNGs work best for logos and icons.

Players & results

Open My games → your game → Players & Results to see, live:

  • Total players, rounds, amount wagered and paid out, payout rate
  • Rounds per day and top winners
  • Every player with balance, rounds, wagered, won and last seen, searchable and sortable
  • A live feed of results, for example "ali_khan: Landed on x5, +250", filterable per player
  • CSV export of players and rounds

Players you test with from the Customize preview are not counted.

Security

  • Keep the license key in an environment variable on your server. Never in front-end code, mobile apps or git.
  • Lost or leaked? Use Integrate → Rotate key. The old key stops working immediately.
  • Optionally list your websites under Integrate → Allowed websites. Browsers will then refuse to show the game on any other site. (Mobile WebViews are not affected by this setting.)
  • Results are decided on our server with a cryptographically secure random generator. Players can't change a result from the browser, and the odds are never sent to the game.
  • Session links expire after 15 minutes.
Treat every playUrl as belonging to one player. Do not share one link between users.

FAQ

Do my players need an account?

No. They only pick a username. If your app already has users, pass username when you create the session and they skip that step.

Is the in-game currency real money?

No. It is play currency tracked per player. Your own system can react to round events if you want to connect it to something real.

Can two players use the same username?

Not inside the same game. Usernames are unique per game license. The same name can exist in a different license.

A player ran out of coins.

The game offers a one-tap free refill back to the starting balance.

I see "Session expired".

The link is older than 15 minutes. Call your endpoint again (the SDK's reload() does this).
