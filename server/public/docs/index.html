Quick start

  1. Create an account and copy your API key.
    Sign up at {{HOST}}. Your API key (mgs_…) is shown once right after sign-up and any time you press Rotate under API key in the dashboard. It is one key for your whole account, whichever games you own.
  2. Buy a game and note its game ID.
    Each game you own has a game ID (lic_…), shown in the dashboard, on the API key page and in GET /api/v1/games.
  3. Add one endpoint to your backend.
    It calls POST {{HOST}}/api/v1/sessions with the API key and the game ID and returns the playUrl to your front-end. See the examples (Node.js, Python, Java, PHP, cURL).
  4. Show the game.
    Open that playUrl in an iframe (website) or a WebView (Flutter, Android, iOS), or use the 3-line JavaScript SDK. Players pick a username and play.
Try it before you code: dashboard → your game → Customize. The preview on the right is the real game.

How it works

  • API key (mgs_…): the secret that proves a request comes from your account. One per account. Use it only on your server.
  • Game ID (lic_…): which of your games to open. You can own many; the same key serves all of them. It is not secret.
  • Play link (playUrl): a temporary link created by your server. It expires after 15 minutes, so it is safe to give to a browser or app.
  • Player: whoever plays. They pick a username the first time (unique inside that game), or you pass their name from your own login so they skip that screen. Balances and history are saved per username.
  • Customization: images, video, sounds, texts, rules and odds are set in the dashboard. Every session loads that game's settings.

Server examples: create the session

Replace GAME_ID with your game ID. Keep the API key in an environment variable named MINIGAME_API_KEY. Your front-end calls your /game-session endpoint, never ours.

Many games, one key. Just send a different gameId. You never manage more than one secret.
Create a new session each time a player opens the game. Do not cache or reuse a playUrl for more than a few minutes.

Show the game

Your front-end asks your endpoint for the play link and shows it.

The games are built for portrait screens (like a phone) and scale to fit any box: they fill the height and use your theme background for the rest. Recommended size: 480 x 760 or the full screen of a phone.

Android needs <uses-permission android:name="android.permission.INTERNET"/>. iOS needs nothing extra for https links. In React Native use react-native-webview and read events from onMessage.

Events from the game

Every event is { source: "minigames", type, data }. Websites get them through the SDK's onEvent (or window.addEventListener('message')), Flutter through the MiniGames JavaScript channel.

typedataWhen
login{ username, balance }The player is signed in
ready{ game }The game is on screen
round{ game, round, bet, win, hits, balance }A round was paid. hits lists the winning option codes (more than one when the bonus triggers).
exit{}The player pressed the back button. Close the game or navigate away.
error{ message }Web SDK only: your session endpoint failed

Events are for your UI (analytics, your own rewards). The authoritative record of every round is on our server and visible in your dashboard.

Customizing a game

Open My games → your game → Customize. Every visual is an asset slot: drag a file onto it, save, and the live preview updates.

AreaYou can change
LookBackground (image, SVG or video), wheel frame and disc, hub, ribbon, bet boxes, every button, logo, avatar, colors
AnimationsAmbient loop behind the wheel, win celebration, lucky-77 celebration: video (MP4/WebM), sprite sheet or image
SoundBackground music, spin, tick, chip, win and lose sounds (MP3 / OGG / WAV / M4A)
RulesBet options (name, multiplier, icon, badge), wheel layout and odds, bonus chance, chips and their values, starting balance, max bet, round timing
TextsEvery label, the how-to-play steps and all popup titles

Upload limits: images 3 MB, SVG 300 KB (scripts and external links are rejected), video 10 MB, audio 4 MB. Transparent PNG/WebP/SVG work best for icons; WebM keeps transparency for effects. Anything you do not upload keeps the default.

Players & results

Open My games → your game → Players & results to see, live: total players, rounds, wagered and paid out, payout rate; rounds per day and top winners; every player with balance, rounds, wagered, won and last seen (searchable, sortable); a live feed of results (for example "Round 1042: Lucky 77. Bet Lucky 77 30000") filterable per player; and CSV export. Players you test with from the Customize preview are not counted.

Security

  • Keep the API key in an environment variable on your server. Never in website JavaScript, a mobile app, a public repository or a screenshot.
  • Lost or leaked? Dashboard → API key → Rotate key. The old key stops working immediately for all your games, and the new one works for all of them.
  • Optionally list your websites under game → Settings → Allowed websites. Browsers then refuse to show the game anywhere else (mobile WebViews are not affected).
  • Results are decided on our server with a cryptographically secure random generator. Players cannot change a result, and the odds are never sent to the game.
  • Play links expire after 15 minutes. Treat each one as belonging to one player.
If your front-end ever contains mgs_, rotate the key now.

Troubleshooting

SymptomCause and fix
401 Invalid API keyHeader must be exactly Authorization: Bearer mgs_…. If you rotated the key, update your server.
400 gameId is requiredSend {"gameId":"lic_…"} in the JSON body (Content-Type application/json).
404 Game not found for this API keyThe ID belongs to another account. Copy it again from the dashboard or GET /api/v1/games.
Game shows "Session expired"The link is older than 15 minutes. Call your endpoint again (the SDK's reload() does this).
Blank frame on your siteCheck "Allowed websites" in the game settings, and that your page uses https.
No soundBrowsers need one tap before audio can play. The first tap on the game unlocks it.

FAQ

Do my players need an account? No, only a username. Pass username when you create the session to skip even that.

Is the in-game currency real money? No. It is play currency tracked per player. React to round events if you want to connect it to something real.

Can two players share a username? Not inside the same game. The same name can exist in a different game.

A player ran out of coins. The game offers a one-tap free refill back to the starting balance.
