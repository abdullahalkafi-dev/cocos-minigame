# Questions from a client's developer, answered

Asked by the team building a client website and Flutter app on top of the platform (user-created rooms, history, fake coin shop). The answers are written against the real behavior, and the features marked **new** were added because of these questions (see [audit log](../operations/audit-log.md)).

| # | Question | Answer |
|---|---|---|
| 1 | Per-round history API? | **New.** `GET /api/v1/games/{gameId}/players/{playerId}/rounds?limit=&before=&room=` returns room, round, winning result, bet, win, net, bets by option and time, newest first. No webhooks needed to build a history screen. |
| 2 | Per-bet detail in `round.settled`? | **New.** Every entry of `players` now has `bets: [{ option, amount, win }]` (stakes added up per option). The rounds API has the same, plus a `label`. Rounds played before this change have `bets: null` in the API. |
| 3 | Room and round in transactions? | **New.** `bet` and `win` entries have `room` and `round` (other entries have `null`). |
| 4 | Webhook per game or room? `gameId` always present? | One address per account (not changed). `gameId` is present in every event except `webhook.test`, and `livemode` says live or test, so filter on `gameId`. A per-game address is on the roadmap. Because the rounds API now exists, a missed webhook is never a gap: read the history from the API. |
| 5 | Private rooms, `online` for one room? | A room key alone never gets anybody in: **only your server can create a session for a room** (API key), so a room is private by design; check your own invite code, then create the session. **New:** `GET /rooms/{key}` returns one room with `online`; `GET /rooms` is paged (`limit`, `offset`, `total`). |
| 6 | Room cap, `createdBy`/`metadata`, auto-delete? | **New.** Cap is now **5,000 rooms per game** (was 200); `too_many_rooms` is returned beyond it. Rooms have `metadata` (up to 10 text values, never shown to players) and `deleteWhenEmptyMinutes` (1 to 10,080 or `null`): the room is deleted after nobody has been in it that long, checked every minute. `main` is never deleted. A player holding a session for a deleted room is moved to `main`. |
| 7 | `main` defaults and settings? | Capacity unlimited (`null`). Yes: `PUT /rooms/main` changes `capacity`, `overrides.chips`, `overrides.maxPerTarget`, `overrides.timing`, `metadata`. (Call `GET /rooms` once first; it creates `main`.) |
| 8 | Balance refresh after `credit`? | Live. When you credit a player who has the game open, the balance updates on screen within about a second (WebSocket push, or the next poll). No reload and no message from you needed, so no `refreshBalance` message exists. |
| 9 | `needCoins` and the `balance` event? | There is **no `balance` event**. Events are `login`, `ready`, `round` (has the balance after the round), `needCoins`, `exit`. `needCoins { balance }` fires when the player taps a chip or bet they cannot afford, in **managed and seamless** games (a seamless game used to miss it; fixed). The server also sends the `player.needs_coins` webhook, at most once per player and 5 minutes. |
| 10 | Round clock defaults? Shared clocks? | betSeconds 20, spinSeconds 6, resultSeconds 6 (a 32 s round). Each room runs its **own independent clock**; rooms cannot share one. Round numbers start at 1001 per room. Rooms can override the timing (betting 8-120 s, spin 3-15 s, result 3-20 s). |
| 11 | One player in several rooms? | Yes. Sessions are independent and are not closed when another is created. The balance is shared; the player counts as online in both rooms; at most 3 live connections per player in total (a 4th closes the oldest). Betting in two rooms at once is fine. |
| 12 | Starting balance in managed mode? Free refill? | **New.** `POST /sessions` accepts `startingBalance` (managed games only): coins for a player that call creates, recorded as a `starting` ledger entry; `playerCreated` in the answer says if it applied. Free refill exists only in **demo** mode; in managed and seamless it is refused (`refill_disabled`) and the game shows no refill button, so there is nothing to avoid. |
| 13 | Webhook delivery to our domain? | No allow-list. Any public `https://` address works. Save `https://api.gamehub.joura.info/webhooks/minigame` on the API key page and press *Send test event*. The address is shared by live and test games: events carry `livemode: false` for test games, so check it. Private and local addresses are refused. |
| 14 | Rate limits? `Retry-After`? | Sessions 300/min, wallet calls 600/min, transactions, rounds, rooms and leaderboard reads 300/min, per key. A `429` has `Retry-After` (seconds) and `RateLimit` headers. An address sending 120 wrong keys or tokens in a minute is blocked until the minute ends. |
| 15 | Allowed websites vs the Flutter WebView? | Confirmed: it only sets the game page's `frame-ancestors`, which matters when a web page embeds the game in an iframe. A WebView that opens the game URL directly (or a Flutter app) is not framed and is unaffected. With only `https://gamehub.joura.info` allowed, your website can embed the game and the app WebView works. |
| 16 | Amounts? Maximum balance? | Whole numbers only. One `credit`/`debit` is 1 to 1,000,000,000,000. There is no fixed balance cap (safe integer limit about 9 quadrillion). |
| 17 | More games? List of games and prices? | Only `lucky-wheel` today. `GET /api/store` (no login) lists the catalog with prices in demo credits; `GET /api/v1/games` lists the games your key can open. A new game needs its own game id (buy it in the dashboard). |
| 18 | Test copy without buying again? Rotate the key. | A game is either live or test (Settings → Environment). The demo store is free (10,000 demo credits at sign-up, 5,000 per top-up), so buy a second copy, set it to *test*, and use the `mgs_test_` key; it never touches live data. Rotate the live key on the API key page when setup is done (it stops the old one immediately). |

## Also useful to know

- Round history is only for finished rounds of real players (dashboard preview players are never included).
- Each room's winning result is hidden until betting closes.
- Everything is in the [OpenAPI document](https://minigame.joura.info/openapi.json) and the [integration guide](https://minigame.joura.info/docs/).
