# Game client architecture (Cocos Creator)

Cocos Creator 3.8, TypeScript, 2D, WebGL2. The game is built **entirely in code**: there is one scene, and `Boot.ts` creates the canvas, camera, loading screen, HUD and the chosen game at runtime. Every image, video, sound and text comes from the buyer's configuration.

```
cocos/assets/scripts/
  Boot.ts               canvas, camera, scaling, session bootstrap, login, starts the game
  core/                 the reusable game library
    Api.ts              HTTP client for /api/play/*, typed state (WheelState)
    GameBase.ts         Game base class and GameCtx (what every game receives)
    Media.ts            spawnMedia(): shows any slot (image, SVG, sprite sheet, video)
    Art.ts              procedural graphics: panels, gradients, glow, coins
    Widgets.ts          Button, label, toast
    Hud.ts              balance, refill prompt, error handling
    Loader.ts           branded loading screen
    Login.ts            username screen (guest mode), fatal error screen
    Sfx.ts              WebAudio sounds + custom audio slots
    Particles.ts        particle layer (sparks, confetti, coins)
    Ticker.ts           per-frame callbacks
    Background.ts, Host.ts, Util.ts
  games/
    index.ts            slug -> game class registry
    lucky-wheel/
      LuckyWheel.ts     controller: state sync, frame loop, spin, betting
      popups.ts         how to play, history, my bets, ranking, winners
      effects.ts        decorative effects: ripple, bursts, result icon, coin flights
      types.ts, format.ts
```

## Rules

- **Never load an asset directly.** Use `spawnMedia()` / `spawnSprite()` with the slot from `ctx.cfg.assets`, so a buyer's SVG, sprite sheet or video works everywhere and an empty slot falls back to the default.
- **The client renders, the server decides.** A game polls the state endpoint and animates what it gets. Optimistic updates (a bet's chip flying) are reconciled with the server answer.
- **Layout is anchored to the screen edges** (`ctx.vh` is the visible stage height). The stage is scaled down on narrow phones. Design height is 1280 units.
- **Design is final.** The artwork comes from the client's Figma; add motion and polish, never change layout or art.
- A game is split into a **controller** and **views** (popups, effects) that receive a narrow interface (`WheelScene`, `PopupHost`) instead of reaching into the controller's internals.

## Build

```bash
npm run build:games      # runs Cocos Creator headlessly (about 1-2 minutes), post-processes, copies to server/public/games
npx tsc --noEmit -p cocos   # fast typecheck without opening Creator
```

Creator never exits on its own in headless mode, so the build script waits for the build output and then stops it. Set `COCOS_CREATOR_DIR` if Creator is not at `C:\ProgramData\cocos\editors\Creator\3.8.8`. New `.ts` files get `.meta` files generated by Creator; commit them.

The engine is trimmed to 2D modules (about 1.9 MB, about 430 KB over the wire with Brotli).

## Host messaging

The game talks to the page or app around it with `postMessage` (websites) and a JavaScript channel named `MiniGames` (Flutter and other WebViews): events `ready`, `login`, `round`, `needCoins` (managed or seamless wallet: the player tapped something they cannot afford, open your shop) and `exit`.
